What is inside the file, and what is not

Inside: accounts, transactions, import runs, open issues, settings — the whole SQLite database, byte for byte.

Not inside: the passphrase. It exists only in your head and on whatever paper you wrote it on.

Two files, two jobs. vault-key-0001.bpk holds the data key, sealed with your passphrase. bankpipe-*.bpdb are the snapshots, encrypted with that data key. Changing the passphrase rewrites only the key file, so the archive survives it.

How it is protected: AES-256-GCM. The key file uses PBKDF2-HMAC-SHA256 at 600,000 iterations with a fresh 16-byte salt. The header of every file is authenticated, so the iteration count cannot be downgraded and a snapshot cannot be relabelled as another vault's. A wrong passphrase and a modified file both simply fail to open.

Size: a manual snapshot is gzip-compressed before it is encrypted, so a 10 MB database usually takes 1–3 MB in Drive. The automatic copy is different: it is split into fixed 64 KiB blocks, each encrypted on its own, and only the blocks that changed are uploaded. A one-transaction edit typically sends one or two blocks plus a small manifest.

Retention: the last 14 daily snapshots plus one per month for a year. Manual snapshots are never overwritten — each backup is a new file — so two devices cannot destroy each other's history. The key file is never pruned. The automatic copy is one copy replaced in place, separate from that history, and deleting it never touches a manual snapshot.
